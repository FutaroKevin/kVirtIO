# Service Documentation: KvirtIO Log Collector

The **KvirtIO Log Collector** is a python-based service designed to centralize, structure, and filter log events generated by all KvirtIO watchers. It outputs a consolidated JSON file of the last 24 hours of events, which is consumed by the dashboard for UI-based log inspection.

---

## 📋 Functional Description

The script `kvirtio-log-collector.py` aggregates log records from the SLES systemd journal, filters them by specific syslog identifiers, derives event levels from the log text, enforces log retention (retaining only events from the last 24 hours up to a cap of 5000 events), and writes them to a group-readable JSON file.

### Aggregated Syslog Identifiers

The collector queries journalctl for the following tags:
-   `KvirtIO-Host` (Host Watcher)
-   `KvirtIO-IO` (I/O Watcher)
-   `KvirtIO-Cluster` (HA Cluster Watcher)
-   `KvirtIO-Multipath` (Multipath Watcher)
-   `KvirtIO-VM` (VM Watcher)
-   `KvirtIO-Network` (Network Watcher)
-   `KvirtIO-HTMLGen` (HTML Generator)
-   `KvirtIO-LogCollector` (The collector's self-logs)

### Log Level Derivation

Since standard journal entries might not always carry explicit severity levels, the collector scans the message body and extracts the status using regex matching:
1.  `CRITICAL` (highest priority)
2.  `ERROR`
3.  `WARNING`
4.  `SUCCESS`
5.  `INFO` (default)

---

## 📈 Process Logic

1.  **Read Journal**: The collector runs `journalctl` for the specified tags and retrieves log entries from the last 30 minutes.
2.  **Load Existing Logs**: It loads `/var/log/kvirtio/logs/kvirtio-events.json` to keep continuity.
3.  **Retention & Deduplication**:
    -   Removes entries older than 24 hours.
    -   Deduplicates incoming entries against existing ones.
    -   Orders events with the newest at the top.
    -   Caps the total count at 5000 events to prevent high memory/storage usage.
4.  **Atomic Write**: Writes the updated logs to `/var/log/kvirtio/logs/kvirtio-events.json` using a temporary file and atomic replace. File permissions are set to `0644` so they can be read by the Apache web server group.

---

## 📄 JSON Output

**Output path**: `/var/log/kvirtio/logs/kvirtio-events.json`

**Example**:
```json
{
  "generated_at": "2026-06-10T14:30:00",
  "event_count": 1,
  "events": [
    {
      "timestamp": "2026-06-10T14:28:45",
      "source": "KvirtIO-Cluster",
      "level": "CRITICAL",
      "message": "[cluster_db] Quorum lost: 2/5 nodes active."
    }
  ]
}
```

## ⚙️ Systemd Integration

### Service Unit (`kvirtio-log-collector.service`)
```ini
[Unit]
Description=KvirtIO Log collector Service
After=network.target

[Service]
Type=oneshot
User=kvirtwatch
ExecStart=python3 /usr/local/bin/kvirtio-log-collector.py
PrivateTmp=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/tmp

[Install]
WantedBy=multi-user.target
```

### Enabling and Starting
```bash
sudo cp systemd/kvirtio-log-collector.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now kvirtio-log-collector.service
```

## 🪵 Log Inspection

Self-logs of the log collector are sent to syslog with the tag `KvirtIO-LogCollector`.

*   **View log collector logs**:
    ```bash
    journalctl -t KvirtIO-LogCollector -f
    ```
*   **Log message examples**:
    -   `INFO: Avvio raccolta log.`
    -   `INFO: Raccolti 15 nuovi eventi dal journal.`
    -   `INFO: File eventi aggiornato: 125 eventi totali in /var/log/kvirtio/logs/kvirtio-events.json.`
